# Автономный агент CoffeeIT

Локальный исполняющий агент: **мозг — локальная модель Ollama**, память и файлы — Google Drive, поиск — интернет. Он берёт задачи из «Реестра задач», ищет контекст в Drive и сети, создаёт документы в структуре «AI-Агент · Рабочее пространство», пишет отчёт и закрывает задачу в реестре.

Инструкции агента загружены из Drive и лежат в `agent/prompts/`:
- `system.md` — «Системная инструкция AI-агента · v1.0» (роль, зоны полномочий, нейминг, стандарт ответа);
- `scenarios.md` — «Рабочие сценарии и промпты агента» (W1–W8, библиотека промптов).

Короткая памятка по запуску также лежит в Drive: [2026-11-21 · Инструкция · Запуск автономного агента · v1](https://docs.google.com/document/d/13i1lfeqW1jl3cXSlzBn2D3PU5luAP1S7h92SRjQ8DAw/edit) (папка «00 · Инструкции»).

## 1. Мозг (Ollama)

```sh
ollama serve
ollama pull qwen2.5:7b        # модель с поддержкой tool calling
npm run agent -- doctor
```

Подойдут также `llama3.1:8b`, `mistral-nemo` и другие модели с function calling. Модель задаётся в `OLLAMA_MODEL`. Агент не отправляет данные в облачный LLM: запросы идут только на локальный `OLLAMA_BASE_URL`.

## 2. Подключение Drive

Скопируйте `.env.example` в `.env`. Два варианта:

**OAuth (рекомендуется для личного Drive).** В Google Cloud Console создайте OAuth-клиент типа «Desktop app», получите `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`, затем:

```sh
npm run agent -- auth url          # откройте ссылку, разрешите доступ
npm run agent -- auth code '<код>' # вставьте код из адресной строки
```

Команда выведет `GOOGLE_REFRESH_TOKEN` — добавьте его в `.env`. Запрошенные права: Drive + Sheets (чтение файлов, создание документов, обновление реестра).

**Сервисный аккаунт.** Заполните `GOOGLE_SERVICE_ACCOUNT_FILE` (и `GOOGLE_IMPERSONATE` для domain-wide delegation). Для личного Drive без Workspace обычно нужен OAuth.

Настоящие ключи никуда не коммитятся: `.env` и `service-account.json` в `.gitignore`. Подключение Google Drive из Arena (коннектор) доступно только внутри чата; локальному агенту нужны собственные учётные данные — это сделано намеренно.

ID рабочей структуры уже указаны в `.env.example`: папка `AI-Агент · Рабочее пространство`, реестр задач и папка отчётов. Если ID отличаются — переопределите переменные.

## 3. Запуск

```sh
# проверить всё сразу
npm run agent -- doctor

# разовая задача, ответ в терминал
npm run agent -- ask "Сделай дайджест: что изменилось в Drive за 7 дней"

# разовая задача + сохранить отчёт в «06 · Отчёты»
npm run agent -- ask "Проанализируй coffeeIT-finmodel.csv" --save

# автономный проход: взять открытые задачи из реестра, исполнить, отчитаться
npm run agent -- run --once --limit 3

# непрерывный режим (опрос реестра каждые 15 минут)
npm run agent -- run --interval 900000

# безопасная репетиция без записи в Drive
npm run agent -- run --once --dry-run
```

В реестре задача считается открытой, если статус пустой или один из: `открыта`, `новая`, `open`, `todo`. После исполнения агент ставит «выполнено», добавляет ссылку на отчёт и запоминает строку в `.agent-state/processed.json` (чтобы не выполнять задачу дважды).

## 4. Что агент умеет делать сам

| Инструмент | Что делает |
|---|---|
| `drive_search`, `drive_read`, `drive_list_folder` | ищет и читает файлы, в том числе Google Docs/Sheets |
| `web_search`, `web_fetch` | ищет в интернете (DuckDuckGo без ключа, Tavily/Brave с ключом) и открывает страницы |
| `drive_create_document`, `drive_create_folder` | создаёт документы/CSV/markdown и папки только внутри рабочего пространства |
| `drive_save_copy` | сохраняет правку **новым файлом** с пометкой «ред. AI», оригинал не трогает |
| `drive_comment` | комментирует файлы, не меняя содержимое |
| `tasks_list`, `tasks_add`, `tasks_update` | читает и обновляет реестр задач |
| `finish_task` | фиксирует структурированный отчёт «Сделано / Файлы / Требует решения / Дальше» |

## 5. Ограничения (зашиты в коде, не только в промпте)

- **Красная зона закрыта всегда:** удаление, корзина, публичные ссылки, смена прав, передача владения. Даже если модель попросит — инструмент вернёт отказ. `AGENT_ALLOW_DANGEROUS=1` для автономной работы не рекомендуется.
- **Нет записи в корень My Drive:** все новые файлы создаются только внутри рабочей папки (проверка по цепочке родителей через Drive API).
- **Оригиналы не перезаписываются:** только новые версии.
- **Не более 5 изменяющих операций за проход** (жёлтая зона инструкции).
- **Нельзя отправлять письма/сообщения от имени владельца** — агент только готовит текст.
- `web_fetch` блокирует локальные и приватные адреса (SSRF).
- `--dry-run` запрещает любую запись в Drive.

## 6. Как это устроено

```
agent/
  cli.js         команды doctor / auth / ask / run
  agent.js       цикл «модель → инструменты → модель», финальный отчёт
  brain.js       клиент Ollama /api/chat
  tools.js       объявление и выполнение инструментов
  policy.js      зоны полномочий, лимиты, проверка папок
  drive.js       Drive REST + Sheets API, токены OAuth/service account
  web.js         поиск и чтение страниц
  registry.js    реестр задач из Google Sheets
  prompts/       инструкции, загруженные из Drive
  test/          unit-тесты (без сети)
```

Тесты: `npm test`.
